# CardMaker — 《对峙》卡牌编辑器

## 一、项目概述

CardMaker 是一个专为策略卡牌游戏《对峙》设计的桌面卡牌编辑器，基于 **Tauri v2 + React 19 + TypeScript** 构建。它提供四步向导式 UI，允许设计师零代码定义卡牌、技能、条件和效果，并导出 JSON 或 PNG。

### 技术栈

| 层 | 技术 | 版本 |
|---|---|---|
| 桌面框架 | Tauri | v2 |
| 前端框架 | React | 19 |
| 语言 | TypeScript | 5.5 |
| 构建工具 | Vite | 6 |
| 状态管理 | Zustand | 5 |
| UI 组件库 | Ant Design | 6 |
| 后端语言 | Rust | 1.96 |
| 序列化 | Serde / Serde JSON | 1 |

### 当前版本：v0.8.3（2026-05-29）

## 二、设计初衷与目标

### 问题背景

《对峙》卡牌游戏拥有丰富的效果类型和复杂的触发条件体系。传统方式下，策划需要在 Excel 或纯文本中手工编写 JSON，效率低且易出错。CardMaker 的设计目标是：

1. **零代码编辑**：设计师通过 GUI 下拉框、参数面板完成卡牌配置，无需接触 JSON。
2. **即时预览**：每个步骤都实时生成自然语言描述，所见即所得。
3. **原子化模板体系**：效果、条件、消耗均为独立原子模块，新增类型只需新增模板文件。
4. **双向互通**：JSON 导入与导出完全对称，导出的 JSON 可无损导入回编辑器。

### 核心设计原则

- **原子化解耦**：每个效果/条件/消耗是独立 TypeScript 文件，互不依赖。
- **模板注册表模式**：所有原子模块在 `templates/index.ts` 统一注册，新增模块只需两步：写文件 + 注册。
- **枚举驱动**：17 个核心枚举定义所有常量，杜绝魔法字符串。
- **自然语言生成**：`exporters.ts` 负责将结构化数据转换为可读中文描述。

## 四、核心架构

### 4.1 原子化模板体系

整个编辑器的数据模型基于三层原子：

```
效果模板 (IAtomicEffect)         ← 24 个
条件模板 (IAtomicCondition)      ← 12 个
消耗模板 (IAtomicCost)           ← 8 个
```

每个原子模板定义：
- `type`：枚举值，如 `EffectType.DEAL_DAMAGE`
- `name` / `description`：中文名称与说明
- `params`：编辑器中需填写的参数列表（`IParamDefinition[]`）

编辑器中实际使用的是**实例**（`IEffectInstance` / `IConditionInstance` / `ICostInstance`），实例引用模板 ID 并携带用户的参数值。

### 4.2 数据类型体系

| 枚举 | 枚举值数量 | 说明 |
|---|---|---|
| `AttributeType` | 7 | 属性类型（生命/护甲/能量/攻击/防御/速度/暴击率） |
| `CardType` | 8 | 卡牌类型（基础/阵营/职业/武器/宝物/护甲/武学/法术） |
| `Rarity` | 4 | 品质（白/蓝/紫/橙） |
| `Timing` | 14 | 触发时机（立即/回合开始/受到伤害等） |
| `TargetType` | 26 | 目标类型（自身/一个敌人/全体等） |
| `EffectType` | 25 | 效果类型（造成伤害/治疗/获得护甲/淘汰等） |
| `ConditionType` | 12 | 条件类型（拥有标记/属性检查/存活检查等） |
| `CostType` | 8 | 消耗类型（支付生命/弃牌/牺牲单位等） |
| `FilterId` | 12 | 过滤器 ID |
| `SorterId` | 5 | 排序器 ID |
| 其他 | — | `MarkType`, `MarkExpireBehavior`, `StackingType`, `LogicOperator`, `ComparisonOperator`, `ValidationLevel`, `SortOrder`, `RelationType`, `CardCategory`, `ParamType` |

### 4.3 目标选择引擎

`src/target/` 目录实现了一个模块化的目标选择系统：

```
TargetSelector (入口)
  → TargetTypeResolver (解析目标类型 → 初始集合)
  → TargetFilterChain (逐层过滤)
  → TargetSorter (排序)
  → 返回最终目标列表
```

过滤器和排序器均为独立模块，通过 ID 注册，支持组合使用。

### 4.4 四步向导流程

```
Step 1: 选择卡牌类型 → Step 2: 填写基本信息 → Step 3: 配置技能与效果 → Step 4: 预览与导出
```

每个步骤独立组件，状态通过 Zustand `cardStore` 共享。第 3 步是核心交互区，支持为技能添加多组条件组、消耗列表和效果列表。

### 4.5 Tauri 后端

Rust 后端提供 4 个命令：

| 命令 | 用途 |
|---|---|
| `greet` | 测试用问候 |
| `save_card_data` | 保存 JSON 文本到指定路径 |
| `save_card_image` | 将 base64 PNG 图像写入磁盘 |
| `load_card_data` | 从指定路径读取 JSON 文本 |

依赖：`tauri v2`, `tauri-plugin-fs v2`, `tauri-plugin-dialog v2`, `serde`, `serde_json`, `base64 0.22`。

### 4.6 导出系统

`src/utils/exporters.ts` 包含两大功能：
1. **JSON 导出**：生成完整卡牌 JSON，支持重新导入。
2. **自然语言预览**：将技能/条件/效果/消耗转换为流畅的中文描述，如"当一个敌方目标的护甲 ≤ 2 且生命值 ≤ 1 时，直接将其淘汰，跳过濒死阶段"。

## 五、构建与运行

### 环境要求

- Node.js ≥ 18
- Rust ≥ 1.96（需安装到 `E:\rustup`）
- Windows 11

### 开发模式

```bash
npm install
npm run tauri dev
```

或双击 `start-cardmaker.bat`。

### 生产构建

```bash
npm run tauri build
```

构建产物位于 `src-tauri/target/release/`。

### 重要环境变量

```
RUSTUP_HOME=E:\rustup\.rustup
CARGO_HOME=E:\rustup\.cargo
```

## 六、扩展指南

### 新增效果模板

1. 在 `src/templates/effects/` 下创建 `effect-新效果名.ts`
2. 在 `EffectType` 枚举中添加新值
3. 在 `src/templates/index.ts` 中导入并注册到 `effectTemplates`

### 新增条件模板

1. 在 `src/templates/conditions/` 下创建 `condition-新条件名.ts`
2. 在 `ConditionType` 枚举中添加新值
3. 在 `src/templates/index.ts` 中导入并注册到 `conditionTemplates`

### 新增消耗模板

1. 在 `src/templates/costs/` 下创建 `cost-新消耗名.ts`
2. 在 `CostType` 枚举中添加新值
3. 在 `src/templates/index.ts` 中导入并注册到 `costTemplates`

所有新增模块均无需修改现有模块，纯增量开发。
